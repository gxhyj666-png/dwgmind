## 二、选型三原则

1. **能力对齐**：队内既有 Spring Boot / Vue 工程经验 ⇒ 主线留在 Java，Python 只做图形几何边车。
2. **硬件止损**：RTX 3050 仅 4GB 显存，跑不动 7B 多模态模型 ⇒ 大模型走云 API，且**必须可降级**。
3. **依赖最小**：不装 Docker、不引入 Neo4j/向量库/消息队列 ⇒ 每层都用本机已有且已验证的组件。

### 4.2 内部接口（Java ↔ Python 边车，可选）

| 协议 | 端点 | 载荷 |
|---|---|---|
| REST/JSON | `POST /py/v1/ocr` | 图片 → 文本块 + 坐标 + 置信度（需 tesseract） |
| REST/JSON | `POST /py/v1/dxf/parse` | DXF → 规范化图元 JSON（需 ezdxf，可与 Java 解析器交叉验证） |
| GET | `/py/v1/health` | 能力自检 |

> 边界设计：Python 边车**只做无状态几何/OCR 计算**，不持有业务数据；边车不可用时主流程完全不受影响。

### 4.3 第三方接口

| 提供方 | 用途 | 接入方式 |
|---|---|---|
| DeepSeek / 阿里云百炼 | 语义摘要、工艺研判、问答生成 | OpenAI 兼容 HTTP + `LLM_API_KEY` 环境变量，统一超时/重试 |

### 4.4 统一约定

- 统一响应体 `Result<T>{code,message,data,traceId,timestamp}`
- 全局异常处理：业务异常 / 参数校验 / 上传超限 / 兜底异常分级返回
- 大模型调用**必须可降级**：未配置 Key → `RULE_ONLY`，健康检查如实告知
- SSE 与 WebSocket 均设置超时与清理钩子，避免连接泄漏

## 五、关键中间件接入（已在代码中生效）

### 5.1 Redis

```yaml
spring:
  data:
    redis:
      host: ${REDIS_HOST:127.0.0.1}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD:}
      database: 0
      timeout: 3s
      lettuce:
        pool: { max-active: 8, max-idle: 8, min-idle: 0 }
```

| 用途 | 数据结构 | 键示例 | TTL |
|---|---|---|---|
| 解析结果缓存 | String(JSON) | `dwg:parse:{sha256}` | 30 min |
| 打榜实时排行 | ZSET | `dwg:lb:{topicId}` | 赛季内 |
| 接口限流 | String 计数 | `dwg:rl:{key}:{minute}` | 70 s |
| 长任务进度 | Hash | `dwg:task:{taskId}` | 2 h |

> Redis 不可用时全部降级为 no-op，主流程不受影响。

## 七、一页话总结（答辩口播版）

> 我们的技术选型遵循"**能力对齐、硬件止损、依赖最小**"三条原则。
>
> 后端用 **Spring Boot 3.2 + JDK 17**，复用队伍在既往项目里已经跑通的骨架——统一返回体、全局异常、链路追踪；
>
> 图纸解析是**我们自研的 DXF 组码解析器**，不依赖任何重型 CAD 库：DXF 本质是成对出现的组码文本，Java 直接读既稳又可控，25 个图元 40 毫秒解析完；
>
> 语义层做三件事：**空间聚类分零件、最近邻归尺寸、规则识别工艺注记**，并且每一条结论都带溯源坐标——这是让评委"看得见"的地方；
>
> 大模型是**可选增强**：配了 Key 就多一条"结构研判"，没配就纯规则引擎跑，健康检查会如实告诉用户当前是哪种模式。因为本地 GPU 只有 4GB 显存，我们不做本地大模型的假承诺；
>
> 数据层只用本机已经在跑的 **MySQL 8 与 Redis 5**：MySQL 存图元、关系与溯源，Redis 负责解析缓存、打榜排行、接口限流和长任务进度——**没有引入任何新中间件，没有 Docker 依赖**；
>
> 接口层 **REST + SSE + WebSocket**：SSE 让"上传即看到解析进度"，WebSocket 承载多人协同复核；
>
> 前端 **Vue 3.5 + Canvas 2D 世界坐标渲染**，缩放、平移、点结论高亮出处全部可用，无头浏览器 16 项断言全通过。
