## 三、构建过程中修复的关键问题（真实踩坑记录）

这些不是"写代码时的小 bug"，而是把系统从"能编译"推到"真能演示"的关键几步，答辩时可以作为工程能力的例证。

### 1. `JAVA_HOME` 指向已删除目录

- **现象**：所有 Spring Boot 工程无法构建，`java -version` 为 1.8.0_102
- **根因**：`JAVA_HOME=D:\Java\Java`（该目录不存在），注册表 `JavaSoft\JDK\17.0.10` 同样残留失效路径；PATH 命中 JDK 8
- **修复**：JDK 17 实际存在于 `C:\Users\86180\.jdks\corretto-17.0.20.1`，改 `JAVA_HOME` + 前置 PATH，`mvn compile` 验证通过
- **教训**：环境变量一定要回读验证，而不是看设置界面

### 2. `mvnw.cmd` 在本机不可用

- **现象**：`Internal Windows PowerShell error ... Cannot start maven from wrapper`
- **根因**：PowerShell 配置/执行策略问题
- **修复**：直接用已下载的 Maven 3.9.16 完整路径，或用 IDEA 内置 Maven

### 3. 画布空白（最有价值的一个坑）

- **现象**：页面上所有数据都正确（13 条结论、BOM、榜单），但画布一片空白
- **排查过程**：
  1. 首先怀疑数据没加载 → 用 CDP 读运行状态，确认 `entities=25`
  2. 再怀疑渲染分支 → 手动在画布画测试线，像素统计确认 `ctx` 正常工作
  3. 发现 canvas 位图仍是 `300x150` 默认尺寸 → 容器布局与挂载时序问题
  4. 修复 resize 后仍有内容被裁 → 发现 **Y 轴只翻转了坐标、没有翻转取景**，导致上半张图画到画布外
  5. 最终改为**统一世界坐标系 + 变换矩阵渲染**（`applyWorldTransform`），fitView 求包围盒==可见范围
- **教训**：Canvas 渲染问题必须用像素采样验证，不能靠"看起来对"；模板 ref 必须在 `setup()` 返回值里暴露，否则 `ref.value` 永远是 null

### 4. 前端与后端不同源导致 404

- **现象**：5173 上所有 `/api/*` 请求返回 HTML（404）
- **修复**：前端增加 `API_BASE` 解析（同源用相对路径，否则默认 `host:8080`），支持 `?api=` 覆盖

### 5. 浏览器缓存旧 JS 导致"改了没生效"

- **现象**：连续两次截图字节完全相同
- **修复**：静态服务加 `Cache-Control: no-store`，`index.html` 给 JS 加版本号，CDP 侧 `Network.setCacheDisabled`

### 6. PowerShell 写文件带 BOM 导致编译失败

- **现象**：`非法字符: '\uFEFF'`，`需要 class、interface、enum 或 record`
- **修复**：用 `UTF8Encoding($false)` 重写，移除 BOM

## 五、后续可扩展方向

1. **DXF 实体扩展**：INSERT（块引用）、HATCH（填充边界）、SPLINE，以及 DIMENSION 真实测量值解析
2. **PDF 矢量层解析**：PDF 内的路径可直接转图元，比 OCR 路径质量更高
3. **几何校验器**：判断零件轮廓是否闭合、壁厚是否达标，把"识别"升级为"校验"
4. **评测集建设**：用需求大厅里的真实脱敏图纸建 50—100 张标注集，量化 Precision / Recall
5. **Python 边车增强**：接入 ezdxf 交叉验证、OpenCV 轮廓提取、Tesseract 中文标注 OCR
6. **大模型增强**：图纸语义摘要、工艺可行性研判、跨图纸相似结构检索（embedding）
